## 1. 背景与目标

### 1.1 业务背景

羽毛球培训俱乐部普遍用微信群 + Excel 管理排课、签到和课时，存在以下问题：

1. 排课靠人工沟通，改课、调课容易冲突、漏通知。
2. 学员忘记上课、迟到，场地和教练时间被浪费。
3. 课时包剩余次数靠手工记账，容易产生纠纷。
4. 教学视频、动作纠正散落在聊天记录里，难以沉淀。
5. 馆长缺少经营数据（出勤率、续费率、教练课时量）。

### 1.2 产品目标

| 目标 | 衡量指标 |
| --- | --- |
| 排课线上化 | 90% 课程在系统内排定 |
| 降低缺课率 | 缺课率下降 30% |
| 课时透明 | 课时纠纷为 0 |
| 教学内容沉淀 | 每位学员每月至少 2 条视频 / 点评 |
| 智能化 | 三期后 50% 的查询、预约通过智能体完成 |

### 5.9 AI 智能体（四期）

| 编号 | 功能 | 示例 | 优先级 |
| --- | --- | --- | --- |
| A-01 | 查课 | 学员：“我这周还有几节课？” | P3 |
| A-02 | 约课 | 学员：“帮我约周六下午王教练的私教课” → 返回可选时段，确认后下单 | P3 |
| A-03 | 调课 / 取消 | 学员：“把明天的课改到周日” → 检查规则，确认后执行 | P3 |
| A-04 | 查课时 | “我还剩几节课，什么时候到期？” | P3 |
| A-05 | 教练排课 | 教练：“下周二、四晚上 7 点给青少年 A 班排课，1 号场” → 生成排课草稿，冲突提示 | P3 |
| A-06 | 教练查询 | “明天有哪些学员课时不足？” | P3 |
| A-07 | 教学问答 | “反手高远球总是打不远怎么办？” → 结合俱乐部视频库回答 | P3 |
| A-08 | 经营问答 | 馆长：“上个月哪个教练出勤率最高？” | P3 |

智能体设计要点：

1. **只读操作直接执行，写操作必须二次确认**（约课、取消、排课前展示卡片，用户点“确认”才生效）。
2. **权限继承**：智能体只能访问当前用户有权限的数据。
3. **工具调用（Function Calling）**：大模型不直接改数据库，只调用后端已有接口。
4. **知识库**：俱乐部规则、课程介绍、教学视频文字稿作为检索知识库。
5. **兜底**：识别不了意图时转人工 / 给出操作入口。

## 7. 核心业务流程

### 7.1 教练排课 → 学员约课 → 提醒 → 签到消课

```
教练/馆长在后台排课
   ↓ 冲突检测通过
课程发布（指定学员的课直接生成预约）
   ↓
学员小程序约课 → 预占课时
   ↓
开课前一天 20:00 订阅消息 + 短信提醒
开课前 2 小时 短信提醒
   ↓
教练点名签到 → 正式消课 → 课时流水
   ↓
教练写课后点评（可附视频）→ 通知学员
```

### 7.2 调课 / 取消

```
教练调课 → 系统检测冲突 → 通知所有已预约学员（订阅消息 + 短信）
学员取消 → 判断是否在免费取消时限内 → 退回 / 扣除课时 → 候补递补
```
